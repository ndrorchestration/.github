# Ecosystem Repository Baseline — Wave 1 Audit

Date: 2026-09-10
Scope: `ndrorchestration/.github`, `agent-control-plane`, `dgaf-ops`, `Orbit-Driftwatch`

## Purpose

Record the evidence-backed findings from the first baseline propagation wave without creating a second mutable repository-classification SSoT. Portfolio role, lifecycle, relationship, and disposition remain in Notion. Exact implementation and CI state remain in the applicable GitHub repository.

## Shared baseline

`ndrorchestration/.github` now proposes default contribution, security, support, PR, and issue conventions for repositories that do not define local equivalents. These defaults explicitly prevent cross-repository transfer of validation, certification, security status, deployment status, authorization, or empirical efficacy.

The shared evidence standard remains vocabulary/claim discipline only; it is not a global project-status registry.

## Reusable-workflow decision

**No reusable cross-repository workflow is justified by Wave 1.**

The observed workflows have different purposes and evidence semantics:
- ACP: Python package/interpreter compatibility testing;
- dgaf-ops: operational provenance/source-binding validation;
- Orbit-Driftwatch: deterministic Node/application verification and separate Pages deployment.

Combining them merely because they are CI would create false abstraction and blur evidence boundaries. Workflow reuse should wait for at least two repositories with materially identical deterministic validation logic.

## Wave-1 merge rule

A repo-local PR may merge only after exact-head relevant checks pass and the diff remains within the audited scope. The shared `.github` baseline requires its own structural validator because it otherwise has no CI. Missing checks are never reported as PASS.

## Next propagation order

After Wave 1 closes:
1. remaining `KEEP_ACTIVE` primary/research repositories;
2. `KEEP_AS_WORKSTREAM` support/workstream/component/utility repositories;
3. `INVESTIGATE` repositories receive classification audits before implementation;
4. `ARCHIVE` and external-fork repositories receive only provenance/status corrections unless explicitly reactivated.
