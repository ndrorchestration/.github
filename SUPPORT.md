# Support

This is an account-level default for `ndrorchestration` repositories that do not define a local support guide.

## Where questions belong

- Implementation, bugs, tests, releases, deployment state, and project behavior belong in the repository where that behavior lives.
- DGAF/PDMAL governance, experiment authorization, and scientific-state questions belong in `ndrorchestration/DGAF-Framework` and its exact-bound governance/evidence records.
- Portfolio role, lifecycle, and repository relationship are maintained in the ecosystem's Notion classification layer rather than duplicated as mutable status across repositories.
- Shared files in `ndrorchestration/.github` define defaults and conventions; they do not supersede project-local authority.

## Before opening an issue

Check the repository README, local docs, existing issues, and open pull requests. Include the exact revision, environment, reproduction path, and observed behavior when reporting a problem.

Do not report credentials, private data, or exploit details in public issues. Use the applicable `SECURITY.md` for suspected vulnerabilities.

## Evidence boundary

Support discussion, maintainer acknowledgement, issue closure, or a successful workaround is not equivalent to verification of broader correctness, certification, production readiness, or empirical efficacy. Keep claims bounded to the evidence actually produced.
